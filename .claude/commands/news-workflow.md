# 뉴스 수집기 기능 개발 워크플로우

전달받은 인자: `$ARGUMENTS`

아래 단계를 **순서대로** 실행하세요. 각 단계가 끝나기 전에는 다음 단계로 넘어가지 마세요.

## 1단계: 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인합니다.
2. 현재 브랜치가 `main`이 아니면:
   - 현재 브랜치 이름을 보여주며 경고합니다.
   - 커밋되지 않은 변경 사항이 있으면 함께 알립니다.
   - "main 브랜치로 이동할까요?"라고 사용자에게 물어보고 **답을 기다립니다**.
   - 사용자가 동의하면 `git checkout main`으로 이동합니다. 변경 사항 때문에 이동이 실패하면 임의로 폐기하지 말고 사용자에게 알립니다.
   - 사용자가 거절하면 워크플로우를 중단합니다.

## 2단계: 새 브랜치 생성

1. `$ARGUMENTS`가 비어 있지 않으면 그 값을 브랜치 이름으로 사용합니다.
2. `$ARGUMENTS`가 비어 있으면:
   - "어떤 기능을 개발할 예정인가요?"라고 묻고 답을 기다립니다.
   - 답변을 바탕으로 **영어 소문자-하이픈** 형식(예: `add-category-filter`)의 브랜치 이름을 제안하고 사용자의 확인을 받습니다.
3. 브랜치 이름이 영어 소문자·숫자·하이픈 형식이 아니면 변환을 제안합니다.
4. 이미 같은 이름의 브랜치가 있으면 알리고 다른 이름을 요청합니다.
5. `git checkout -b <브랜치-이름>`으로 브랜치를 생성합니다.

## 3단계: 개발 시작 안내

브랜치 생성이 끝나면 다음을 출력합니다.

> **이제 개발을 시작하세요!**

그리고 `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 정리해서 알려줍니다. 최소한 다음을 포함하세요.

- 스택: Next.js(App Router), Clerk 인증, Drizzle ORM + Neon Postgres, Claude API, `rss-parser`, Notion MCP 서버
- 명세 문서: 구현 전에 `PRD.md`, UI 작업 전에 `ui.md`를 먼저 읽을 것
- Next.js 16 / Clerk v7 / Anthropic SDK v1은 학습 데이터와 다를 수 있으므로 설치된 패키지 문서·타입 확인
- 모든 페이지와 `/api/*`는 Clerk로 보호, Claude 출력은 `zod`로 검증
- 수집은 버튼 클릭으로만 실행(cron 없음), 스타일링은 Tailwind CSS
- 명령어: `npm run dev`, `npm run build`, `npm run lint` (테스트 러너 없음)

이후 사용자가 개발을 진행하는 동안 요청에 맞춰 작업을 돕습니다.

## 4단계: 완료 처리

사용자가 **"완료"** 또는 **"done"**이라고 입력하면:

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여줍니다.
2. 변경 내용을 분석해 커밋 메시지를 제안합니다. 이 저장소의 기존 커밋처럼 **한글로 간결하게** 작성합니다 (`git log --oneline -5`로 스타일 확인).
3. 제안한 메시지로 커밋해도 될지 사용자에게 확인하고 **답을 기다립니다**. 수정 요청이 있으면 반영합니다.
4. 확인되면 변경 파일을 스테이징하고(`.env*` 등 비밀 파일은 제외) 커밋합니다. 시스템에서 안내한 Co-Authored-By 문구가 있으면 메시지 끝에 붙입니다.
5. `git checkout main` 후 `git merge <브랜치-이름>`으로 병합합니다.
6. 병합 충돌이 발생하면 임의로 해결하지 말고 충돌 파일을 보여주며 사용자에게 안내합니다.

푸시(`git push`)와 브랜치 삭제는 사용자가 요청하기 전에는 하지 않습니다.

## 5단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여줍니다.

- 브랜치 이름과 병합된 커밋 (`git log --oneline -n 5`)
- 변경된 파일 목록과 주요 변경 내용
- 커밋 메시지
- 다음에 할 일 제안 (예: 푸시, 브랜치 정리)
